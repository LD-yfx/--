# Headless ROS2 / Nav2 integration experiment

This package runs **real Nav2 NavFn, DWB and BT Navigator** with a deliberately simple 2-D differential-drive kinematic simulator. It validates navigation integration and mechanism behavior, **not real localization accuracy**. Odometry is exact; the quality field is an artificial full-grid oracle. It does not replace module-one data or claim SLAM benefits.

The simulator receives the sole `/cmd_vel` stream from Nav2, integrates the differential-drive motion, publishes `/odom` and TF (`map → odom → base_link → laser`), raycasts `/scan` from geometric obstacles, and publishes a static `/map`. Dynamic obstacles appear only in the lidar rays. An independent disk/rectangle collision check stops penetration and counts attempted collisions; acceptance requires zero attempts, so this check cannot silently turn unsafe controller behavior into a passing result. Missing commands stop motion after 0.4 s.

Global costmap order is static, lidar obstacle, inflation, quality; the local costmap uses lidar obstacle and inflation. `allow_unknown=false`. The BT replans at 2 Hz with no recovery motion on an impossible path; this differs from the standalone Python replanning policy. Global quality penalties are already generated by the production `quality_cost_node` from the synthetic `QualityGrid` stream.

```bash
source /opt/ros/humble/setup.bash
source module_two/ros2_ws/install/setup.bash
export ROS_DOMAIN_ID=74
ros2 run quality_navigation_demo integration_runner --require-installed --output "$PWD/module_two/results/ros_navigation"
```

The runner launches and stops its own process group. `--static-only` runs the initial two cases; `--existing-stack` uses an already launched stack. Each result explicitly records `mode: full` or `mode: static_only`. `--require-installed` verifies that the runner, simulator, and core cost node report installed module paths and SHA256 hashes matching the workspace sources; source overlays therefore cannot silently satisfy release acceptance. The simulator and core node report their own actual runtime module identities. Workspace script `module_two/integration/run_installed_navigation_test.sh` runs the installed full suite; `run_navigation_test.sh` is only a source-overlay development helper.

Intermediate reports always contain `completed: false` and `all_passed: false`. Full acceptance requires exactly the five ordered cases and all eleven named checks, including installed-code identity. Static-only acceptance requires its two cases and four checks (five with `--require-installed`). A finished failing test can have `completed: true` and `all_passed: false`; incomplete or exceptional runs cannot pass. The development overlay helper may exercise all mechanisms, but full acceptance remains false until the installed-code check passes.

To inspect manually:

```bash
ros2 launch quality_navigation_demo headless.launch.py
ros2 service call /simulation/quality_enabled std_srvs/srv/SetBool '{data: true}'
ros2 service call /simulation/top_blocked std_srvs/srv/SetBool '{data: true}'
ros2 service call /simulation/top_blocked std_srvs/srv/SetBool '{data: false}'
ros2 service call /simulation/all_blocked std_srvs/srv/SetBool '{data: true}'
```

Send a `NavigateToPose` action in frame `map` with goal `(4.3,0)`, yaw 0. `/simulation/reset` returns to `(-4.3,0,0)` and removes dynamic events. Never reset while a navigation action is active. Do not run module one's route driver concurrently.

Acceptance artifacts: `results.json` records action status, executed trajectories, plans, time bounds, collision attempts, code provenance, and checks; per-case CSVs and `trajectories.png` provide inspection; `nav2_launch.log` records plugin loading and server behavior. Arrival requires both Nav2 success and independently measured simulator distance to the goal ≤0.30 m. Checks cover real master-cost changes, quality-induced route changes, closed-loop arrival, replanning around a new obstacle, obstacle removal, and bounded failure/stopping with a completely blocked route. Failures remain in the report and cause a nonzero exit. Earlier development runs are retained in `results/ros_navigation/debug/`.

Quality is refreshed synthetically every 0.5 s with sample count 100, variance 0. The lower corridor's score changes from 0.99 to 0.03. This extreme field is an intentional integration stimulus, not a fitted robot/environment model. Scientific comparison of quality mappings and sparse/noisy observations belongs to the separate experiments.
