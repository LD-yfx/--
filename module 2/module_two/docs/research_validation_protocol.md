# 模块二研究验证协议

本协议规定下一阶段要取得什么证据，以及如何防止工程演示被误写成定位性能结论。它是**待执行的实验协议，不是已经通过的验收报告**。已有人工质量场、理想里程计和离线规划结果继续保留，作为回归基线。

协议版本：1.1（实现阶段明确定位器、校准路线及任务总时限，尚未采集正式 D/T 数据）。正式采集前将本文件、实际地图、配置和代码哈希写入实验 manifest。任何后续修改均记录版本、原因和受影响的实验；不能根据测试结果悄悄修改阈值、删掉失败场景或选择有利种子。

## 1. 研究问题与允许的结论

优先回答三个问题：

1. 实际模块一产生的质量分数，与独立定位器的真实位姿误差是否相关？这种关系在视觉退化、激光退化和联合退化下是否一致？
2. 在同一导航系统中，质量代价是否改善定位误差或任务完成情况？如果改善，需要付出多少路径长度、时间和停车代价？
3. 与简单线性质量映射相比，方差、样本量、时效和窗口更新是否提供可重复的增益？

不得用以下结果代替答案：更高的模型自身质量分、较低的自身规划目标、人工指定的“真实误差”、只有 CSV 能解析、只有 Nav2 能到达，或增加测试条目数量。

本阶段采用 WSL Ubuntu 22.04 / ROS2 Humble 中的 **AMCL 1.1.20 激光定位基线**。激光与 RGB 来自实际 Gazebo 传感器；轮式里程计显式使用 diff-drive 的编码器积分 `odometry_source=0`，AMCL 独占 `map→odom`。模块一运行实际特征提取及规则融合代码，禁用旧真值加噪代理、真值路点驱动，并设置 `fusion.model_path=""`、`fusion.strategy="rule"`、`fusion.mlp_enabled=false`，避免旧代理误差标定模型混入。

Gazebo 随机种子及按传感器时间索引的测量退化种子均写入 manifest。当前安装的 AMCL 不暴露随机种子参数，因此不得宣称全部定位器随机过程可按种子逐位重放。研究结论的边界如下：

| 采用的定位器 | 允许的结论 | 不允许的推广 |
|---|---|---|
| AMCL 等仅依赖激光、地图和里程计的定位器 | 多模态质量评分对激光定位导航的影响；视觉质量是否引发不必要绕行 | 多模态融合定位精度得到提高；视觉定位能力得到改善 |
| 实际使用视觉和激光等多种观测的融合定位器 | 在已实现、已记录的融合配置下，质量规划对融合定位导航的影响 | 推广至未测试的传感器组合或定位算法 |
| 真值加噪代理、直接真值里程计 | 接口、异常处理和机制演示 | 独立定位性能或真实 SLAM 精度改善 |

若先完成 AMCL 实验，该阶段可以形成有效但范围有限的研究结果；多模态融合定位结论仍为未验证。仅视觉退化是 AMCL 组的必要检验场景，不能因预期无收益而删除。

## 2. 实验架构与真值隔离

目标链路为：场景与传感器模拟 → 实际模块一评估器 → 质量统计/地图 → 模块二映射 → 实际 Nav2 规划控制 → 机器人运动。独立定位器同时接收其规定的传感器输入，输出导航所需估计位姿与 TF。

“实际模块一输入”指运行模块一真实代码并处理图像、激光、里程计等传感器消息，不能由实验脚本直接填写全图质量、样本数或方差。仿真传感器仍需明确标注为仿真输入，不称为实机采集。

### 2.1 数据所有权

| 数据/节点 | 来源及使用约束 |
|---|---|
| 场景真值位姿 | 仅供模拟器生成物理观测、独立评价与必要的初始状态设置使用；不能持续发布为导航估计位姿 |
| 传感器消息 | 由场景、机器人运动和预先冻结的退化过程生成；不能依据待测方法名称或定位误差修改观测 |
| 轮式里程计 | 模拟编码器/运动观测及其噪声、偏置或滑移；不能直接复制世界真值位姿当作估计 |
| 独立定位器 | 禁止订阅评价真值、待测方法的人工误差标签；输出实际估计位姿、状态和协方差（如有） |
| 模块一质量 | 禁止读取真实定位误差以生成 Q；用于空间建图的位姿来自约定的估计链路 |
| 导航 TF | 每条变换只有一个发布者；不能同时保留模拟器的理想 map→odom 变换和定位器的估计变换 |
| 障碍物地图 | 可使用各方法共享的先验地图；拥有先验地图不等于允许持续获得真值位姿 |
| 评价器 | 只读真值、估计、质量、目标、路径、控制与事件日志，不反馈控制或质量修正 |

允许已知初始位置或给定初始位姿分布，但所有方法使用相同设置，并记录初始误差。若以真值初始化，应明确这是起点条件，不是运行期间真值定位。

### 2.2 必须保存的架构记录

正式运行前保存实际节点、订阅/发布话题、TF 发布者、定位器名称与版本、模块一及模块二运行路径与哈希。重点确认：

- 模块一不再由人工全图质量发布器替代。
- 导航使用独立定位结果；理想位姿发布器不再覆盖导航 TF。
- 输入图像/激光与定位器收到的观测对应同一场景、同一时间。
- 真值消息只进入评价支路；模块一生成 Q 的公式没有真实误差输入。
- 所有格的 `last_observed` 表示实际观测时间；不能因发布地图而把未观测区域刷新为新数据。

发现上述隔离不成立时，该运行标记为 `invalid_evidence`；可保留作调试，但不能进入定位性能统计。

## 3. 地图、种子与开发/测试分离

### 3.1 固定分组

已有双通道人工质量场是开发/回归数据，不作为新的独立测试地图。

| 集合 | 最低配置 | 用途 |
|---|---|---|
| 开发集 D | 2 张新地图；种子 0、1、2 | 接口调试、校准、参数和控制阈值选择 |
| 冻结测试集 T | 2 张未参与调参的地图；种子 100、101、102 | 主比较与模型消融 |
| 动态测试集 E | T 中预先指定的 1 张地图；相同 3 个测试种子 | 障碍出现、消失、完全封路、质量退化与恢复 |

开发与测试地图不能只是同一几何的小噪声副本。建议 D 包含非对称绕障和有特征房间，T 包含有回环的房间连接与易混淆的长廊/开放区；最终以实际生成地图的独立拓扑、布局和哈希为准。地图确定后先冻结，再观察待测方法结果。

每张地图预先指定起终点、机器人外形、最大速度、障碍物地图和可通行参考路径长度。至少有可选路线，且包括首次进入的未知区域与回访区域；不能仅沿已知高质量轨迹验证。

### 3.2 冻结退化过程

每张地图均测试四种条件：正常、仅视觉退化、仅激光退化、联合退化。具体退化必须作用于传感器生成过程，例如视觉纹理/照度/遮挡、激光有效回波比例/噪声/几何可观测性；不能直接令“低 Q 区域”的真实误差变大。

每个条件记录退化区域、强度、发生时间、传感器频率与噪声参数。相同地图、种子、条件下，各方法共享相同场景和外生随机过程。推荐按场景时间或空间位置索引噪声，避免不同路线导致随机数调用次数改变后，某方法碰巧获得更好的观测。

随机种子独立于方法。各方法的执行次序用固定随机排列，避免总是几何基线先跑；每次试验重置定位器、地图历史、局部/全局代价图、控制状态和随机过程，禁止继承上一方法采集的质量地图。

## 4. 第一阶段：Q 与真实误差的校准

### 4.1 先采与规划无关的数据

在 D 地图上，先用相同预定路线或相同几何基线采集数据。该阶段不让完整质量模型决定路线，减少“只看自己选择的好路线”的选择偏差。路线需覆盖四种退化条件、低覆盖区域和重复观测区域。

已固定开发地图为 `dev_asymmetric` 与 `dev_rooms`，分别经安全中间点 `(0,-2.5)` 与 `(0,4.25)`，再到目标、再次经过中间点、返回起点。四种传感器条件都使用相同路点，确保开发校准实际经过退化区域。正式 T 地图为 `test_ring` 与 `test_corridors`，采用固定目标再返回起点，允许待测方法自由选择可行路线。某方法避开退化区域本身不是无效证据，需记录实际退化帧数和暴露时长。最低 D 矩阵为 `2×3×4=24` 次，另有 171 次 T/动态试验，不包括联调运行。

各地图的参考路径由固定 0.1 m 网格、0.32 m 足迹的保守四邻格搜索生成，包含路点与格中心间的短连接；它是可通行参考，不是最短连续曲线。具体距离及总任务源时钟预算保存在各地图 `metadata.json`。预算按全程计算，多路点逐段递减剩余时间；不会每到一个路点就重新获得完整预算。墙钟保护单列为 `max(600 s,4×源时钟总预算)`，启动及采集收尾耗时单独记录。

每条记录至少包含：源时间、地图/种子/条件、估计位姿、真值位姿、定位器状态、模块一 Q_v/Q_l/Q_fused（实际输出哪些就记录哪些）、格均值/方差/计数/最后观测时间、known 标志、机器人速度与传感器有效性统计。

### 4.2 时间与坐标对齐

- 所有在线数据使用同一 ROS 源时钟；墙上时钟只统计运行耗时，不能计算格年龄。
- 评价时将真值插值到估计位姿时间；位置线性插值、角度解包后插值，禁止跨越定位重置或时间回退进行插值。
- 默认最大配对时间差为 50 ms；若实际传感器频率不支持，应在采集前冻结新的阈值并解释，不能事后放宽以补好结果。
- 地图坐标与真值世界坐标的静态变换在运行前固定。不能为每个方法做全轨迹最优配准以消除本应计入的定位偏差。
- 估计位姿缺失要单独计数；不把没有位姿输出的困难时段从成功率中删除。

### 4.3 校准分析

计算平移误差 `e_pos(t)=||p_est(t)-p_gt(t)||` 与环绕后的偏航误差 `e_yaw(t)`。将 Q 与当前误差关联，并另报告 Q(t) 对后续 1 s 最大误差的预测关系；未来误差只由离线评价器计算，不能进入在线 Q。

最低输出：

1. 按地图和退化类型分组的散点图、Spearman 相关，以及质量越高误差是否确实越低。
2. 固定 10 个等宽质量区间中的样本量、误差中位数/P95、超阈值比例；低样本区间显式标记，不能平滑成确定结论。
3. 默认超阈值定义为平移误差 >0.30 m 或偏航误差 >10°。这些是本次比较的预注册工作阈值，不是通用安全标准；若平台要求不同，必须在正式采集前更改并冻结。
4. 分别检查 Q_v、Q_l、Q_fused，特别是 AMCL 组中的“视觉 Q 下降但激光定位仍准确”。这类反例需要保留，用于判断融合分数是否会造成无收益绕行。

相关性只支持关联，不自动证明规划带来因果改善。连续帧不能当作彼此独立的试验；汇总和不确定性分析以完整运行为单位。

如果采用单调回归或其他校准函数，只能用 D 拟合，保存参数后在 T 固定评估。经验风险分、`μ-β√v` 和样本量饱和函数默认仍是启发式评分，不能称为概率、置信区间或已校准不确定度。

若 D 上 Q 与误差没有稳定关系，仍需如实完成并保存校准结果，然后修正质量定义或缩小结论。不能通过在模拟器中加入“Q 越低，定位误差强制越大”的规则制造关联。

## 5. 第二阶段：冻结闭环主比较

主方法固定为三种：

| 方法 | 质量映射 | 其他设置 |
|---|---|---|
| geometric | 质量软代价为 0 | 相同导航规划器、控制器、障碍层、机器人和定位器 |
| linear | 已知格使用 `1-μ`；未知格使用固定约定 | 同上 |
| full | 当前已实现的均值、方差、计数、年龄映射 | 同上 |

三组均运行实际模块一，保持采样与计算负载可比；geometric 只是不用其质量软代价。不能给 full 单独更好的地图、定位器参数、速度上限或初始位姿。

最低主矩阵：`2 张 T 地图 × 3 个种子 × 4 种退化 × 3 种方法 = 72 次闭环试验`。每次记录完整轨迹而不只记录最终到达。

质量地图使用相同启动策略：主实验从未知状态开始；若还需测试预采质量地图，应作为独立组，所有方法共享同一冻结预采图，不能与在线未知启动结果混算。

先在 D 选择并冻结 full 参数和质量权重，再运行 T。允许比较少量预先列出的候选参数，但不得在 T 上选择最好组合。gamma=1 为初始基线；若保留 gamma=2，作为预注册敏感性对照单独报告。必须记录权重、β、γ、n0、τ、未知惩罚、窗口秒数、窗口容量及传感器采样频率。

## 6. 第三阶段：组件消融与动态证据

### 6.1 必要消融

在与主矩阵完全相同的 24 个地图/种子/退化组合上，增加 `no_variance`、`no_count`、`no_age` 三组，计 72 次。full 的主矩阵结果直接复用，不重复挑选更好的运行。

要求有真实的样本量、方差和观测年龄变化。不能在所有格 `n=100、v=0、age≈0` 的条件下宣称验证了这些组件。需要报告已知覆盖率、每格计数分布、年龄分布与方差分布，说明消融项在本次试验中是否实际起作用。

窗口更新应额外报告已知→未知、坏格过期→未知、退化后恢复的时间过程。固定统计量时的年龄单调性质，不等于整个窗口系统随时间单调；坏证据被遗忘后惩罚下降是需要测量的行为。

若去掉某组件后性能不变或更好，报告没有观察到该组件增益；不能仅凭公式包含更多项就认定 full 更优。可依据 D 结果提出简化版，新的正式比较需冻结新版本。

### 6.2 动态矩阵

在 E 地图上，用三个固定测试种子和三个主方法执行以下三条完整事件序列，共 27 次：

1. 局部通道出现障碍 → 存在替代路线 → 原障碍移除。
2. 所有路线被封闭 → 安全停止/有界失败 → 再次开放并按统一任务策略恢复。
3. 实际传感器质量退化 → 部分质量格老化或失效 → 传感器恢复和实际重新观测。

事件发生时间、位置、持续时间预先固定。障碍应进入传感器观测与障碍处理链路；不能直接向规划器写入答案。禁止在机器人实体已占据的位置生成障碍，否则试验定义不再是正常避障。

主比较中的停车/恢复策略必须一致。若新增“质量差时减速或停车”，应另设控制策略对照，不能只给 full 启用后把收益归因于代价映射。尚未实现质量停车时明确标记 `not_supported`，不把无路停车等同质量退化停车。

## 7. 统一指标与失败口径

所有主试验、消融和动态试验采用以下定义：

| 指标 | 统一定义 |
|---|---|
| 到达成功 | 在时限内任务返回成功，真值距目标 ≤0.30 m，且无碰撞；若任务规定终点朝向，另要求偏航误差 ≤15° |
| 运行时限 | 先按各地图参考可通行距离 L_ref 和统一最大速度 v_ref，冻结 `max(90 s, 4×L_ref/v_ref+30 s)`；相同场景各方法一致 |
| 碰撞 | 独立真值几何检查记录机器人足迹与障碍相交；计接触事件，并记录被模拟器阻止的穿障运动步，不能只因模拟器阻止了运动就报告无碰撞风险 |
| 定位误差 | 估计时间上的平移 RMSE、中位数、P95、最大值；偏航 RMSE/P95；另报告超阈值时间比例 |
| 位姿输出缺失 | 有效评价覆盖率；连续缺失 >0.5 s 记一次估计中断。覆盖率 <95% 的运行不能只用剩余片段声称定位性能通过 |
| 路径长度 | 真值执行轨迹累计长度；规划路径长度作为次要诊断，不能代替实际行驶距离 |
| 总耗时 | 目标接受至成功/失败/超时的时间，包含停车、重规划和恢复等待；另记录运动时间和静止时间 |
| 重规划 | 记录请求次数与真正路线切换次数；重复发布同一路径不能算一次有效改道 |
| 停车 | 障碍/无路或已实现质量策略触发后，实际线速度 <0.02 m/s 且角速度 <0.05 rad/s 持续至少 1 s；记录触发至停止延迟 |
| 恢复 | 障碍移除或有效新观测恢复后，到重新出现可执行路径、恢复运动、最终到达分别计时；记录是否需人工干预或重新下发目标 |
| 失败 | 超时、导航主动失败、碰撞、定位持续中断、节点崩溃、人工干预、数据证据无效分开记录；不得删行 |

完全封路阶段的预期结果是停车或有界失败，不能计入普通可通行场景的到达成功率。恢复目标是否自动继续或统一重新发送，应在运行前冻结，并对全部方法一致。

失败试验仍保留路径长度、失败前耗时、定位误差和覆盖率；不能因为行驶较短而被解释为路径更优。同时展示“全部试验任务结果”和“成功试验性能”，禁止只报告成功子集。

首要比较为 full 对 linear，其次为 full 对 geometric。以同一地图/种子/退化组合做配对差值，展示每次试验与分组汇总；报告误差改善与路径/时间代价的联合结果，不用不同方法各自的 objective 数值直接比较。

最低矩阵的种子数量有限，因此以描述性结果和配对效应为主，不据此宣称广泛统计显著性。若给出置信区间或重采样结果，重采样单位必须是完整运行或地图，不能用数千帧伪造大样本量。

## 8. 负结果、重试与退出规则

在看到 T 结果之前，预注册并保留以下可能结果：

- Q 与真实误差无稳定关系，或不同退化类型下关系相反。
- full 与 linear 无差异、误差更差、成功率更低或绕路时间更长。
- 方差、计数、时效任一组件没有可观察收益。
- 视觉质量下降让 AMCL 导航无必要绕行；这可能意味着评分与被测定位器不匹配。
- 窗口遗忘坏证据导致重新进入差区域，或未知惩罚过强导致停滞。
- 动态事件导致无法恢复、反复切换路线或有界失败。

节点启动失败、配置错误等基础设施问题允许修复后重试，但原始运行保留，并记录原因、版本和替代关系。算法碰撞、定位失效或超时不是可随意重跑至成功的基础设施错误。修复改变算法后，受影响的正式对照应按同一版本重新执行，不能混用新旧最优结果。

不得以剩余计算预算、执行时间长或当前结果不好为由跳过真值隔离、校准、主比较、必要消融或失败记录。可以分批执行并保存中间产物；未完成时报告已完成数量、剩余矩阵和具体阻碍，状态保持未完成。只有用户明确改变任务范围，才可缩减最终要求，并在报告中保留范围变更记录。

## 9. 结果产物与完成门槛

建议结果目录以协议版本和定位器命名，避免覆盖现有人工场实验。例如 `results/research_v1/<estimator>/`。

至少交付：

- `manifest.json`：协议版本、代码/安装包/地图哈希、定位器、传感器、TF、参数、分组、种子、执行次序、冻结阈值。
- `runs.csv`：每个预注册运行一行，包含状态、失败原因、全部主指标、证据路径和重试关联。
- 原始传感器/质量/估计/真值/控制/事件日志或 rosbag，以及明确的数据字段说明。
- 校准图表、分退化类型的 Q–误差关系、配对方法比较、消融、质量地图覆盖与年龄统计、动态停车恢复图。
- 未运行、无效、失败、重试、负结果列表；不能用 `all_passed` 一个布尔值替代完整性审计。

按三阶段逐项报告：

| 阶段 | 完成条件 |
|---|---|
| 独立定位与校准 | 真值隔离核对通过；实际模块一输入链路有证据；D 校准数据与分析完成，含无相关性的可能结果 |
| 闭环主比较 | 参数/测试集冻结；72 次主矩阵全部有有效运行或明确失败记录；所有方法统一评价 |
| 组件与动态验证 | 72 次必要消融和27次事件序列全部有记录；实际统计变化已确认；负结果、停车和恢复如实报告 |

“实验完成”表示问题得到完整、可审查的回答，不要求 full 一定获胜。若只证明 AMCL 导航机制，应按此范围结论；若尚无真实多模态融合定位器，则多模态定位精度提升仍明确为未验证。
