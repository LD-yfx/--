# 模块二定位质量感知导航实施方案

本模块承接模块一的定位质量地图，将其转为导航代价，完成路径规划、动态避障和可复现实验。模块一原始解压目录保留作参考；需要的接口扩展在模块二工作区内的副本实现。完整实机部署由模块三承接。

## 已核实的输入条件

- ROS2 Humble，Ubuntu 22.04；本机已有对应 WSL 环境。
- 模块一发布 `/localization_quality/quality_map`，类型为 `nav_msgs/OccupancyGrid`，`-1` 未知、`0..100` 从低质量到高质量。
- 模块一 `QualityGrid` 内部记录均值、样本方差、样本数、最后观测时间，但原消息只发布均值。
- 已有地图是轨迹采样图；地图默认在 odom 坐标系，离线图与实时图的范围和分辨率不同。不能将其当作障碍物地图。
- 模块一归档中的定位输出为真值加噪代理；49.83% 是加权误差代理改善，不是闭环导航或真实 SLAM 精度改善。原始 bag 未在 ZIP 中提供。

## 具体工作和验收

1. 数据接口：读取模块一完整 CSV 和元数据；新增可选的稀疏质量统计 ROS 消息。校验维度、数值、时间、坐标系，原 OccupancyGrid 接口保持可用。
2. 数学映射：实现几何基线、线性质量、非线性质量和完整模型，给出性质测试和参数解释。输出质量代价不占用障碍物保留编码。
3. 导航集成：Python 代价节点发布 `nav2_msgs/Costmap`；C++ Nav2 插件将质量软代价叠加到障碍层后，保持未知、内切膨胀和致命障碍语义，支持 TF、范围变化和失效回退。
4. 规划与控制：离线 A* 用于可控对比；ROS 中使用 Nav2 规划与局部控制，提供启动和配置。关闭原数据采集路点驱动，避免 `/cmd_vel` 冲突。
5. 动态处理：实现消息超时、每格老化、障碍出现/消失后的重规划；控制器使用实时障碍物。无路时停止，禁止穿越障碍。
6. 验证：算法性质、CSV 兼容、障碍语义、C++ 插件编译、ROS 话题链路、路线选择、动态障碍和消融实验。代理实验与真实定位实验分别标注。

## 拟验证的项目创新

研究问题是：在质量图稀疏、不同位置采样量不同、质量随时间变化时，如何给规划器提供保守且可解释的软代价。

设单格质量均值为 μ，样本方差为 v，观测数为 n，距最后观测的时间为 a。以下均为经验评分，不声称是校准概率或统计置信区间。

```
q_conservative = clip(μ - β sqrt(v), 0, 1)
b = (1 - q_conservative)^γ
r = (1 - exp(-n/n0)) exp(-a/τ)
R = b + (1-r) max(0, R_unknown-b)
C_quality = round(C_max R)
```

未知格直接取 `R_unknown`。在均值、方差、样本数不变的条件下，年龄增加只会把低风险向保守先验提高。参数 `β≥0, γ>0, n0>0, τ>0, 0≤R_unknown≤1, 0≤C_max≤252`。

地图的消息发布时间不等于各格观测时间。新增统计消息携带每个已观测格的 `last_observed`。兼容原均值图时明确使用保守的降级模式，不能凭空重建方差或采样次数。

新增统计接口默认使用有界滑动窗口（10 秒、每格最多 256 样本），独立于模块一原有累计质量地图；可设置窗口为 0 恢复累计统计。窗口过期后未再观测的格回到未知，以免一次新样本把长期历史均值误当成新统计。窗口内样本仍可能相关，样本支持度不是独立样本置信度。旧数据风险只向 `max(base, R_unknown)` 单侧回退，不承诺所有陈旧格收敛到同一值。

窗口完全过期会遗忘好、坏两类证据：若旧格惩罚高于未知惩罚，删除该格后可能降低到未知惩罚。因此，上述年龄单调性只适用于统计量固定的映射函数，不能扩展成整个窗口系统的时间单调性保证。

路径目标为对可通行路径累计 `distance × (1 + weight × normalized_cost)`；碰撞检查与软代价独立。离线目标与 Nav2 各规划器的具体实现分别记录，不能把离线 A* 的最优性证明直接用于 Nav2。

创新候选包括上述有界、单调的证据与时效映射，以及在模块一跨模态质量图上的实证验证。幂函数、A*、Nav2 插件和基础动态避障作为已有方法或工程工作，不声称首创。是否优于简单线性模型必须由实验决定；负结果也保留。

## 实验设计

固定障碍物、起终点、规划器、机器人半径和动态事件，比较几何基线、线性质量、非线性质量、完整模型，以及去掉方差/采样量/时效的消融。本轮使用事先固定的工程参数，未进行自动标定；后续标定必须使用独立开发场景，并保留独立测试集。

至少覆盖双路线、稀疏观测、陈旧高质量图、质量恶化与恢复、动态障碍封路与移除、完全无路。记录路径长度、质量代价积分、低质量暴露、成功率、碰撞、重规划次数和耗时。只有运行独立定位器并以真值评估，才能报告真实定位误差改善；人为质量场和噪声代理只支持行为/机制验证。

## 实施结构

`ros2_ws/src/quality_navigation_msgs`：完整质量统计消息。

`ros2_ws/src/quality_aware_navigation`：共享 Python 模型、CSV 读取、离线规划、ROS 代价节点、实验与可视化。

`ros2_ws/src/quality_nav2_layer`：C++ Nav2 代价层。

`ros2_ws/src/localization_quality`：模块一源码副本，仅增加可选统计输出与必要配置。

`tests/` 与 `results/`：集成验证和带来源的实验产物。

先完成模型与接口，再完成 Nav2 编译和话题链路，随后完成规划/动态实验，最后逐项审计验收。仅通过静态检查或单元测试不代表完整导航验收。
